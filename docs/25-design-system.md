# Design System 规范

**状态：规则与底层组件选型已确认；正式共享包、Theme Provider、两个 Console 的启动状态接入以及共享菜单与弹窗已实现，其余公共组件和完整验收矩阵仍按后续 Issue 交付。**

本规范定义 Platform Console、Tenant Console Shell 与官方业务 Remote 共用的视觉、组件、反馈、键盘和焦点语义。架构边界见 [ADR 0037](adr/0037-browser-surfaces-use-one-shared-design-system.md)，Tenant 品牌边界见 [ADR 0036](adr/0036-tenant-access-owns-controlled-tenant-brand-profiles.md)。本规范不证明共享包、正式组件、Remote 或浏览器闭环已经实现。

## 1. 所有权与消费边界

- 唯一公开 UI 包为 `@saas-forge/design-system`；内部可以按 `tokens`、`icons`、`components`、`patterns`、`styles` 和 `testing` 等稳定子路径组织。
- Platform Console、Tenant Console Shell 与 Remote 不得直接使用底层组件库、导入 Design System 内部文件、定义另一套同类公共组件或注入全局样式。
- Design System 独占全局样式、Theme Provider、公共组件外观和公共交互。`app-runtime` 只拥有启动状态，不拥有启动、加载、失败、404 或致命错误的视觉组件。
- 领域页面只拥有领域数据、领域动作和领域组合，可以使用局部作用域样式排列领域内容，但不得改变公共组件的颜色、形状、状态或交互。
- 缺少无领域含义的能力时，必须先评审并扩展 Design System；不提供复制后再治理的临时例外，也不向消费者暴露任意内部样式入口。

## 2. 版本与 Remote 治理

- MVP 的两个 Console 与全部官方 Remote 使用完全相同的 Design System 版本。
- Shell 独占全局样式和当前 Theme Provider，Remote 不重复注入全局样式。
- 后续 Manifest 声明 `designSystemVersion`；不一致时必须在执行 Remote 代码前拒绝加载。
- 第三方 Remote、多版本兼容范围和独立升级不属于 MVP，出现真实需求后另行决策。

## 3. 视觉基线

- 风格为专业、克制、清晰；颜色主要表达重要操作和状态，不使用装饰性强渐变、发光或大面积高饱和颜色。
- 桌面页面适度紧凑；数据表格可以比普通表单更紧凑，但关键标签、操作和错误信息不得缩小。MVP 不提供用户可切换的密度模式。
- 使用操作系统自带的中英文字体栈，不下载产品专属 Web Font。
- 控件和表面使用轻微圆角；阴影只用于弹窗、浮层等确有层级含义的表面，不以大圆角、卡片或阴影装饰普通布局。
- 空间尺寸来自以 `4px` 为基础的语义间距，常用值为 `4px`、`8px`、`12px`、`16px`、`24px` 和 `32px`；消费者不得引入无语义的任意间距。
- 使用同一套简洁线条图标，且只由 Design System 对外提供。重要操作同时显示图标和文字，删除、停用、恢复等含义不能只靠图标表达；正式引入图标依赖时单独核验并锁定版本。
- 动画只用于解释弹窗、反馈、加载和状态切换，不使用持续或装饰性动画；操作系统要求减少动态效果时取消或大幅缩短。

## 4. 主题与品牌

- 同时提供浅色与深色主题，默认跟随操作系统设置；MVP 不增加手动主题开关。
- 平台第一版默认主色为 `#2563EB`，只由 Design System 的单一语义 Token 提供，Console 与 Remote 不得直接写入色值。
- 平台主色后续可以集中替换，但必须重新验证浅色、深色、对比度和视觉快照后发布。
- Tenant Brand Profile 只改变允许的显示名称、素材、主色和强调色。系统优先保留 Tenant 选择的颜色方向，自动生成浅色和深色主题下可辨识的实际颜色与前景色；仍无法满足对比度和状态辨识要求时拒绝保存。
- Tenant 品牌不得改变状态颜色、布局、组件、交互或无障碍约束。

## 5. 页面布局与响应式

- 数据表格页面可以充分使用可用宽度；普通表单限制在适合阅读和填写的内容宽度，不把字段无条件拉伸到整个大屏幕。
- 表单默认单列；只有两个短小且关系密切的字段可以并排，窄屏必须恢复单列，视觉、键盘和错误阅读顺序保持一致。
- 固定验证 `1440px`、`1280px`、`768px`、`390px` 和 `360px`。产品以桌面管理为主，但窄屏核心流程必须可完成。
- 窄屏保持表格语义和信息顺序，通过受控横向滚动并优先保留名称与关键操作，不自动将每一行改造成另一套卡片交互。

## 6. 表单

- 字段可见标签统一放在控件上方并左对齐。
- 用户离开已编辑字段时校验该字段，提交时再校验全部字段；不在用户尚未完成输入时逐字符报错。
- 字段错误显示在对应控件附近；表单级或依赖服务错误显示在表单顶部。失败后保留全部已填写内容，并将焦点移动到第一个需要处理的问题或表单级错误摘要。
- 存在未保存修改时，关闭弹窗、返回或切换页面必须先确认是否放弃；MVP 不提供自动草稿。
- 提交期间保存按钮显示进行中状态并阻止重复提交，表单内容保持可见；成功后显示明确结果，失败后允许原地修改和重试。

## 7. 表格

- 使用明确的服务端分页，不采用无限滚动。
- 填写筛选条件后通过“查询”或 Enter 一次应用；“重置”恢复默认条件并重新查询，不按每个输入字符连续请求。
- 只有服务端明确支持的列显示排序能力；MVP 每次只允许一个排序字段。
- 批量选择只在当前页有效；翻页或改变查询条件时清除选择并明确告知用户，不保留不可见的跨页选择。
- 操作列固定在右侧，窄屏横向滚动时仍保持可见。每行最多占用三个操作位置：操作总数不超过三个时直接显示；超过三个时直接显示前两个，第三个位置显示“更多”，危险操作与普通操作在菜单中明确分隔。
- 首次加载显示表格加载状态；重新查询时保留旧内容并标记正在更新。
- 无任何数据、筛选无结果和加载失败使用不同状态。筛选无结果可以重置条件；加载失败保留查询条件并允许重试。

## 8. 反馈、空态、加载态与错误态

- 成功操作同时更新当前内容并显示短暂、非阻塞的成功反馈。
- 需要用户处理的失败信息持续显示在相关区域，直到问题解决或用户主动关闭，不能只依赖自动消失的消息。
- 空状态使用简洁图标、明确原因和至多一个合理的下一步操作，不使用大型装饰插画。
- 页面或表格首次加载显示内容轮廓；按钮提交在按钮内显示进行中状态；局部刷新只标记对应区域。
- 除应用首次启动外，不使用全屏加载层阻断其他仍可使用的功能。

## 9. 危险操作

- 普通保存不确认。
- 停用、撤销和可恢复删除使用确认弹窗，明确显示操作对象和后果。
- 永久删除或大范围撤销等不可恢复操作还必须输入对象名称或指定文字。
- 危险确认的默认焦点位于取消操作；按 Enter 不能直接执行危险动作；Esc 只代表取消。
- 操作完成后，对象仍存在时焦点返回原触发按钮；对象被移除时依次移动到下一行、表格标题或空状态，不能丢失到文档起点。

## 10. 键盘与焦点

- 使用 Tab 导航时，当前交互元素显示清晰的主色焦点环；鼠标点击时不强制显示。
- Tab 顺序与页面从上到下、从左到右的视觉和文档顺序一致，消费者不得通过自定义顺序制造跳转。
- Esc 只关闭最上层菜单、提示或弹窗并恢复触发点焦点；有未保存内容时先进入放弃确认。
- 查询条件中的 Enter 执行查询；普通按钮支持 Enter 与空格；多行文本框中的 Enter 只输入换行；危险操作不能由 Enter 直接执行。
- MVP 不增加自定义全局快捷键，只支持浏览器和可访问组件的通用键盘语义。
- 路由切换后焦点移动到新页面主标题，并通过可访问页面状态通知读屏软件。

## 11. 组件范围与展示册

Design System 先维护完整公共能力清单，再随真实产品页面逐步实现，不提前制作没有消费者的高级组件。第一批至少包括：

- 主题、Token、图标、按钮和链接；
- 输入框、密码框、选择框、复选框、字段错误和表单错误汇总；
- 普通弹窗与危险确认弹窗；
- 成功提示、警告和持续错误提示；
- 加载、空数据、失败和 404；
- 页面标题和标准页面布局；
- 表格、查询条件、分页、“更多”菜单和文字提示。

图表、富文本和拖拽设计器等高级能力只在出现已确认的真实需求后评审。仓库建立私有组件展示册，集中呈现组件的中英文、浅色、深色和关键交互状态，并作为使用说明、视觉快照和回归入口；具体展示工具在正式实现首批组件时确定。

## 12. 组件基础选型

底层组件基础确定为 **Ant Design 6.6.2**。它只能由 `@saas-forge/design-system` 内部依赖和封装，Platform Console、Tenant Console Shell 与 Remote 不得直接导入 `antd`、引用 Ant Design 全局样式或覆盖其内部选择器。

Design System 使用 Ant Design 的 `ConfigProvider`、主题算法和 Design Token 作为底层能力，再通过本规范定义的语义 Token 与公共组件形成唯一公开接口。业务消费者只认识 SaaS Forge 的组件名称、属性和状态语义，因此后续替换底层组件库时，迁移范围应被限制在 Design System 内部。

选型前在不修改正式页面的隔离位置制作了 Ant Design 6.6.2 与 React Aria Components 1.20.0 的同场景原型，包括：

- 带服务端分页、查询、单列排序、当前页选择、固定操作列和“更多”菜单的数据表格；
- 标签上方左对齐、离开字段校验、错误汇总、提交状态和未保存保护的表单；
- 可恢复与不可恢复危险操作确认，覆盖默认取消、输入确认、Esc、Enter 和焦点恢复。

选型时使用以下顺序：

1. 键盘、焦点或读屏存在无法接受的问题时直接淘汰；
2. 比较表格、表单和弹窗对本规范的覆盖程度；
3. 比较实现复杂度、维护活跃度、升级风险和最终文件大小；
4. 使用同一套 SaaS Forge 视觉规则比较，不按候选默认外观决定；
5. 向用户展示证据并由用户确认最终依赖。

原型的生产构建将两个候选拆分为独立代码块；在同一原型中，Ant Design 候选压缩后约 `233.19 kB`，React Aria Components 候选压缩后约 `90.22 kB`。这只是原型体积，不代表正式 Design System 的最终大小。Ant Design 提供了更完整的后台表格、表单、反馈和弹窗组合能力，代价是更大的初始文件与更严格的封装、按需加载和升级回归要求。用户已确认选择 Ant Design 6.6.2。

原型还验证出 Ant Design 表格的分页与通用 `onChange` 会同时触发；封装层必须根据变更类型区分分页和排序，防止翻页被错误重置。该行为需要固定为自动化回归测试。原型不算正式产品功能，不勾选 MVP 完成项。

## 13. 验证与支持范围

- 支持现代 Chrome、Edge、Firefox 和 Safari，不支持 Internet Explorer。
- 每次修改公共组件必须自动检查组件功能、键盘操作、基础无障碍、中英文、浅色/深色和关键稳定状态视觉快照。
- 必须验证 Platform Console、Tenant Console Shell 与代表性 Remote 使用同一版本、同一主题入口和同一公共交互。
- 静态门禁禁止消费者导入底层组件库、内部 Design System 文件、全局 CSS 或覆盖公共组件的选择器。
- 创建共享包、组件能渲染或单个应用测试通过都不足以完成 MVP；只有共享消费、边界门禁和相应浏览器证据全部成立，才能勾选 [MVP 开发计划](16-mvp-development-plan.md)中的 Design System 事项。
