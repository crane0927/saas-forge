# Issue #176：管理员初始化、恢复与 Quota 结果

本票在 Tenant 详情增加管理员初始化、业务进度、不可变初始 Membership 回读和原发起人恢复。Tenant、初始化与 Entitlement 各自提供权威结果；页面不通过初始化成功推算 Quota，也不宣称通知已送达。

## 实现边界

- 新增正式初始化读取与恢复 OpenAPI，补齐原初始化命令的 503 / Retry-After 声明。公共状态为未开始、处理中、需显式恢复、补偿中、补偿完成可新尝试、成功或失败；不暴露内部阶段、租约、邮箱、请求指纹或恢复 Key。
- 初始化 ID 固定指向一个根工作流。恢复时重新授权当前平台管理员并校验原 actor，原请求与 Key 从服务端读取。其他管理员可看业务进度，不能接手原尝试。
- 删除应用对已完成初始化根记录的 24 小时回收逻辑；不修改历史 Flyway 迁移。历史稳定结果与原 Key 保持关联。自动恢复未耗尽时只观察；耗尽后可显式继续；只有明确补偿完成的 RETRY_REQUIRED 展示新尝试入口。
- 原发起人恢复句柄仅绑定共享 Runtime 当前会话；页面不保存邮箱、完整请求或凭据。取消和响应丢失显示待确认，不自动生成新 Key。
- 初始化完成后分别重新读取 Tenant 与 Subscription 的实际 max_users 用量。初始管理员展示历史 Membership，未查询通知状态，不把邮件失败显示为激活失败。
- Subscription 与初始化表单共用 Tenant 详情的离开提示，避免多个路由阻断器相互覆盖；局部读取失败保留已确认快照、显示刷新错误，并禁用依赖未知数据的操作。
