# Issue #181：Console 租户访问与接入凭据管理

## 实现边界

- Tenant Console 提供正式 Password Setup 路由，清除邮件 Fragment，密码建立后进入正常登录；密码策略拒绝允许更正，结果不确定先尝试登录。刷新后的公司名称来自共享 Runtime 的权威 Tenant Context。
- 在线且可运行的 Tenant 页面由无凭据 Worker 每 20 秒触发访问状态检查，单次请求最多等待 5 秒；焦点、可见性、联网和页面恢复事件触发核验。核验期间遮蔽旧上下文，暂不可用后继续按服务端重试提示核验；401/403 清除会话。Worker 无法启动或运行失败时遮蔽工作台并提示重新加载；睡眠、冻结和离线期间不声称满足主动提示时限。
- Tenant Access 从现有耐久工作流读取当前生命周期结果和允许动作；继续操作使用已读取的工作流 ID，冻结恢复与解除冻结分开。耐久 `operationId` 是刷新后仍可显示的排查引用。
- OAuth 创建、轮换、吊销和补领均通过共享类型化 Client。IAM 按当前操作者发现已提交操作；提交前或查无记录仍为未知，不能据此新建。补领从服务端保存的原 Key 取回原操作，继续执行原有十分钟、一次替代和重叠窗口规则。
- IAM 提供权威轮换截止与允许动作；Secret 只进入当前页面内存，关闭、导航、刷新及会话失效后不能重读。只读接口不返回 Secret、摘要或恢复请求材料；保留服务 Client 只读。
- 无新增依赖、数据库迁移或 Nacos 配置。开发 HTTPS 的 `/password-setup` 进入 Tenant Console，兼容旧资源及同 Origin 提交的 Gateway 转发。
