# 原生本地开发与完整环境编排分离

现有开发工具把受控浏览器入口、依赖配置、后台进程托管和容器替换绑定，增加日常修改与调试成本。日常开发采用前端原生开发命令、后端 IDE 直接启动和调试，环境初始化及必要基础设施独立准备；完整环境编排保留为集成验收工具，不再是日常应用生命周期的必经入口。

开发者可通过个人配置选择基础设施地址，同时启动多个本机服务，并自行处理同一服务的本机与容器实例冲突。本地运行配置可由文件提供而不依赖 Nacos 配置中心，但跨服务联调仍统一使用 Nacos 服务发现；不新增本地静态下游 HTTP/gRPC 地址方案。敏感值继续使用环境变量或受限凭据文件，测试与生产配置发布规则不变。

## Considered Options

- 继续统一托管前后端启停，或把托管脚本包装成开发命令：拒绝，开发者仍无法直接控制进程、日志与 IDE 调试。
- 通过 HTTP localhost 和绕过 Gateway 简化浏览器联调：拒绝，原生启动不应改变真实浏览器的安全行为。
- 为本地联调同时维护静态下游地址和 Nacos 两套寻址方式：拒绝，增加配置与维护复杂度。

## Consequences

- [ADR 0009](0009-browser-surfaces-use-controlled-origins.md) 的 Local Browser Topology 和 [ADR 0038](0038-browser-sessions-use-intent-bound-slots.md) 的 Browser Session Slot 继续有效；本 ADR 只区分进程管理与浏览器边界，不覆盖这些安全决策。
- [ADR 0034](0034-controlled-service-registry-and-route-catalog.md) 的服务身份与公网路由边界保持有效；Nacos 注册不增加公开 API。
- 当前业务服务中仍存在默认容器 HTTP/gRPC 地址，必须在后续实施中核实并补齐需要的发现路径；本决策的记录不代表原生联调已实现。
- IDE 启动仍以依赖、独立迁移和服务身份准备完成为前提，不把迁移权限或默认业务凭据引入常驻应用。
