# 日常反馈与完整验收采用不同验证范围

根构建包含前端聚合门禁，现有 CI 也存在重复调用完整验证的路径；这些源码事实不能直接证明具体耗时，却说明每次普通修改都执行全套并非唯一选择。日常本机验证按受影响模块与必要集成边界选择，完整验证主要交给 CI，本机保留复现能力；涉及认证、跨服务契约、迁移等边界时扩大相关检查范围。

日常必要验证以 5 分钟内反馈为优化目标，电脑仍能正常开发优先于尽快跑完；无法兼得时允许延长验证时间。通过区分验证职责、减少重复执行和避免同时运行多个重型任务改善体验，不通过删除独有覆盖、把跳过算通过或降低浏览器安全要求换取速度。

## Consequences

- 具体 Issue/PRD 已明确要求的本地浏览器、Fresh Compose 或其他完整验收仍然有效；这项决策不是对历史专项任务的验收豁免。
- 本地相关检查通过、CI 完整验证通过和专项验收完成必须分别记录，不能相互推断。
- 耗时与资源改善必须在相同机器、依赖和验证范围下测量；5 分钟不是所有硬件、首次安装或完整验收的保证。
