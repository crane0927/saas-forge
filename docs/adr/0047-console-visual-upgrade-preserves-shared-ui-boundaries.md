# Console 视觉升级保留共享 UI 边界并先验证真实样板

2026-09-11 的设计访谈确认，以视觉与交互一致性为本次升级的首要结果。输入材料《SaaS Forge 页面设计规范》和《SaaS Forge UI 改造实施计划》是可调整草案；Skyroc v3 是候选视觉参考，其包结构、组件名称和功能清单不直接构成本项目的实施要求。用户随后明确选择 A「分区列表」作为正式实现的视觉基准：标题位于页面背景上，查询区、表格区与创建记录区上下排列。B/C 结构不进入正式实现。视觉选择不表示正式改造或业务验收已完成。

## 共享边界

保留 [ADR 0037](0037-browser-surfaces-use-one-shared-design-system.md) 的唯一公开 UI 包 `@saas-forge/design-system`，在包内组织 Token、主题、布局和页面组件，优先扩展现有 `PageLayout`、`PageTitle` 与 `ServerTable`。不按输入草案另建 `design-tokens`、`theme`、`admin-ui`、`admin-layout` 包，也不只为对齐名称建立重复组件。保留 [ADR 0039](0039-consoles-share-one-authentication-runtime.md) 的 Runtime 与 React Shell 所有权，以及 [ADR 0042](0042-browser-surfaces-atomically-apply-one-resolved-brand.md) 的品牌解析与原子应用边界。

这一选择放弃了按职责拆成多个公开包的方案，避免让视觉升级同时引入消费者迁移和所有权重划；包内职责划分仍可随真实需求完善。

## 首批范围

以 Platform Console 的 Tenant 管理作为真实样板，覆盖其已有列表、查询、分页、创建、详情和反馈状态。字段、校验、权限、导航流程与业务操作语义保持现有行为，不为满足样板清单补建编辑、删除等业务能力。

两个 Console 采用共享的可折叠侧栏视觉结构，保留各自已有路由的名称、顺序和权限判断；菜单较少时不强行分组，不增加占位菜单。顶栏保留现有全局操作，窄视口使用可关闭的导航抽屉。首批不新增多标签页、全局搜索、通知、手动主题开关或用户密度切换。

视觉方向为适度紧凑、轻微圆角与弱边框。浅色主题采用浅灰页面背景，查询和表格使用分块内容区，页面标题直接置于背景上，避免层层嵌套卡片；阴影主要用于浮层。浅色和深色同时完善，继续跟随系统并保留受控租户品牌。具体尺寸、颜色与组件细节由原型确认，不能将草案中的数值直接视为已接受规范。

共享 Token 和组件外观允许同步影响其他消费者，页面结构只主动迁移样板。两个 Console 与代表性 Remote 的回归用于检查共享变化的影响，不作为其他业务页面已完成迁移的证明。

## 原型、规范与验收

先制作隔离视觉原型，展示 Tenant 管理的浅色、深色及侧栏收起效果，数据明确标为示例；用户确认效果后再进入正式实现。原型只回答视觉问题，不代替真实业务验收。

[Design System 规范](../25-design-system.md) 继续作为唯一权威规范，视觉确认后再同步其中与本次方向相关的规则，不新增第二套 UI 规范。本文确定了侧栏与内容区的演进方向，不提前替换既有规范中的具体布局尺寸或默认组件行为。

正式交付需要真实操作及加载、空数据、错误状态的证据，并保留键盘、无障碍、国际化、浅色/深色和桌面 Chrome 布局验证。现有专项要求继续有效；组件名称和数值检查只能作为辅助证据。通过、失败、跳过与未执行分开记录。
